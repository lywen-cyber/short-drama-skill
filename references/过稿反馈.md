# 过稿反馈

用来记下每一轮被退的原因和改法。反复出现的问题，再收进对应细则，不要只改当次稿。本文件是模板；项目里可另建 `过稿反馈.md`。

内部写完、使用者认可、已交稿、外部过稿，是不同状态。不要把「已按清单自检」写成已经过稿。

## 表头

| 日期 | 项目 / 集 | 来源（甲方 / 平台 / 内部） | 被退或被改的原因 | 改法 | 是否已回写细则 |
|------|-----------|----------------------------|------------------|------|----------------|
|  |  |  |  |  | 否 |
|  |  |  |  |  |  |

## 怎么用

- 原因尽量抄对方原话或可核对的意见，不改写成自我开脱。
- 改法写正文里具体怎么改，不写「已优化」。
- 同一类原因出现两次以上，就要考虑改 `references/` 里的对应细则，或在 brief 里写清当次例外。回写后把最后一栏改成「是」并注明文件名。
- 本表默认留在项目内部，不自动打进对外交稿。

这份表会随真实反馈变厚，是本包里最该被持续更新的记录之一。空表本身没有市场结论。
